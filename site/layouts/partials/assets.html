{{- /* assets.html -- global front-end asset pipeline (Hugo Pipes). Replaces the webpack build for the public site. Hugo's `js.Build` (esbuild) is built into Hugo Extended, so the front end no longer needs a separate bundler, a `dist/` directory, or a manifest that had to be kept in sync with the templates. Why this exists: templates used to hardcode `/js/index.js` and `/css/main.css` while webpack emitted `main..js` / `styles..css` into `dist/`, and the Netlify build never ran webpack at all -- so every page shipped with a 404 for its JavaScript. Fingerprinted resources emitted straight from Hugo make that class of bug impossible: the URL is always correct by construction. SCOPE: this partial is for assets that EVERY page needs, and nothing else. It used to also emit customer-portal.css and inventory.scss here. That put 12.5 KB of section-specific CSS on all 56 pages, and -- worse -- because those files loaded after main.css they won the cascade, so the customer portal's Bootstrap-blue `.btn-primary` repainted every primary button on the entire site. Section stylesheets are now attached by the section layouts through the `headStyles` block, which is the only place a page's own stylesheet can be declared. Usage: {{ partial "assets.html" (dict "page" . "mode" "css") }} -> CSS s {{ partial "assets.html" (dict "page" . "mode" "js") }} -> JS {{- end -}} {{- end -}}
